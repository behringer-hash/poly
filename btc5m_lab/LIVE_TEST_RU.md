# Живой тест варианта C1: покупка и удержание до конца окна

Вариант C1: порог 0,03, σ ×1, источник Bybit, переплата 3 цента, покупка не меньше 5 шейров и не меньше $1.
Лимиты (ваши): 10 ордеров и $30 на окно, $100 в сутки, остановка при убытке $20 за сутки.

Живые ордера отправляются только в режиме `live` и только после вашего прямого «да». Режимы `dry` и `sign` ничего не отправляют.

## Подготовка (один раз, на сервере, под пользователем, у которого лежит торговый бот)
```bash
cd ~/btc5m_lab                                 # папка с bot.py (обновите из репозитория)
cp live_config_c1.example.json live_config_c1.json
nano live_config_c1.json                       # впишите funder; остальное уже выставлено
```
Ключ в файл не писать. Если на сервере одновременно работает `lab-collector`, смотрите `free -m` и строку `loop p99`
в консоли бота: если `p99` уходит в сотни миллисекунд, на время теста остановите запись
(`sudo systemctl stop lab-collector`) и потом включите (`sudo systemctl start lab-collector`).

## Шаг 1. dry (без ключа, ничего не подписывается и не отправляется), 1–2 часа
```bash
tmux new -s c1
python3 bot.py --live live_config_c1.json --mode dry --no-chart --clip 5 --single-clob \
    --variants c1:0.03:bybit:1 --latencies 200,300
```
Видно, какие ордера отправил бы бот и какие отсёк бы по лимитам. Выход из tmux: Ctrl+B, затем D.
Остановка бота: Ctrl+C.

## Шаг 2. sign (с ключом: подписывает ордера, но НЕ отправляет), 1–2 часа
```bash
export PM_PRIVATE_KEY=0x...                      # только в этом окне терминала, не в файл и не в чат
python3 bot.py --live live_config_c1.json --mode sign --no-chart --clip 5 --single-clob \
    --variants c1:0.03:bybit:1 --latencies 200,300
```
Проверяется: баланс, правильность `signature_type` (режим сам подскажет), подпись, размер ордера ≥ $1.

## Шаг 3. live — только после моего «да» и вашего подтверждения лимитов
Команда та же, но `--mode live` (бот попросит ввести «ДА»). Аварийная остановка: создать файл `STOP` в папке бота.
Выигрыш нужно забирать (Claim) в интерфейсе Polymarket: бот этого не делает.

## Сверка с реплеем (после 12–24 часов live)
Живые ордера пишутся в `bot_data` (`live_orders`, `live_order_meta`, `live_windows`). Сверка:
`python live_vs_paper.py bot_data_c1 --variant c1`, плюс те же сигналы я прогоняю на записи сервера через `risk_sim.py`.
Ожидание по реплею: доля исполнений ≈ 18–23% при ответе сервера ≈ 250–300 мс, прибыль на сигнал ≈ +2…+3 ц/шейр.
Если живая доля исполнений заметно ниже или прибыль около нуля, останавливаемся и разбираемся.
