# Сервер записи данных и обмен отчётами через git — подробная инструкция

## Что мы строим

```
   ВАШ СЕРВЕР (Lightsail, Стокгольм)                       GITHUB (репозиторий behringer-hash/poly)
 ┌──────────────────────────────────────┐              ┌──────────────────────────────────────────┐
 │ lab-collector  — пишет сырые данные  │              │ ветка claude/peaceful-mendel-yvwgus      │
 │   бирж и Polymarket в /home/lab/data │              │   код + задания (папка jobs/)  ◄─ пишет  │
 │   (в git НЕ попадают)                │   забирает   │                                   Claude │
 │                                      │◄─────────────│                                          │
 │ lab-runner — раз в 5 минут:          │   задания    │ ветка server-results                     │
 │   1. тянет код и задания из git      │              │   маленькие отчёты (текст, таблицы)      │
 │   2. выполняет новые задания         │─────────────►│   ◄─ читает Claude                       │
 │   3. отправляет отчёты               │   отчёты     └──────────────────────────────────────────┘
 └──────────────────────────────────────┘
```

* Я (Claude) **не подключаюсь к серверу**. Я пишу скрипт-задание и сохраняю его в репозитории. Сервер сам его забирает, выполняет и кладёт отчёт обратно. Через несколько минут я читаю отчёт.
* Сырые данные остаются на сервере. В репозиторий уходят только небольшие отчёты (файлы больше 2 МБ отбрасываются автоматически).
* Серверу нужен только **исходящий** интернет. Ничего открывать в брандмауэре Lightsail не надо.
* Торговли здесь нет: служба записи запускается с `--no-paper --no-wallet`, ключа кошелька на сервере для неё не нужно.

## Решение, которое надо принять до начала

**На этом же сервере крутится живой бот?** Тогда запись с `--extra-feeds all` (сотни сообщений в секунду) может замедлить его, а задержка — как раз то, что мы измеряем. Надёжнее взять **второй дешёвый инстанс Lightsail в том же регионе (Стокгольм)** только под запись. Если живого бота на сервере нет — используйте его же.

## Что понадобится

1. Доступ к консоли Lightsail (aws.amazon.com/lightsail) и права администратора на репозиторий GitHub `behringer-hash/poly`.
2. Ubuntu 22.04 или новее на сервере (так обычно и есть), примерно 2 ГБ памяти (на меньшем установщик сам создаст файл подкачки).
3. 20–30 минут.

## Шаги

### Шаг 0. Откройте терминал сервера
Lightsail → **Instances** → ваш сервер → оранжевая кнопка **Connect using SSH**. Откроется чёрное окно с командной строкой — это и есть терминал. Команды ниже вставляются в него целиком (вставка: правая кнопка мыши или Ctrl+Shift+V) и выполняются клавишей Enter. Выполняйте их **по одной группе** и сверяйте результат.

### Шаг 1. Создайте отдельного пользователя `lab`
Он нужен, чтобы запись данных и задания работали отдельно от вашего торгового бота и его секретов. Команда `chmod 700` закрывает его папку от других пользователей сервера.
```bash
sudo adduser --disabled-password --gecos "" lab
sudo chmod 700 /home/lab
```
Если пишет `The user lab already exists` — всё в порядке, идите дальше.

### Шаг 2. Создайте ключ для GitHub
```bash
sudo -iu lab
mkdir -p ~/.ssh && chmod 700 ~/.ssh
ssh-keygen -t ed25519 -N "" -C "lab-server" -f ~/.ssh/id_ed25519
cat ~/.ssh/id_ed25519.pub
```
Последняя команда выведет одну длинную строку, которая начинается с `ssh-ed25519` и заканчивается `lab-server`. **Скопируйте её целиком** (это *публичный* ключ, его можно показывать). Приватный ключ (`id_ed25519` без `.pub`) никому не показывайте и не вставляйте в чат.

Приглашение командной строки теперь начинается с `lab@...` — вы работаете от имени пользователя lab.

### Шаг 3. Добавьте ключ в GitHub
1. Откройте https://github.com/behringer-hash/poly/settings/keys (вы должны быть владельцем репозитория).
2. Нажмите **Add deploy key**.
3. **Title**: `lab-server`. **Key**: вставьте скопированную строку.
4. Поставьте галочку **Allow write access** (сервер должен уметь отправлять отчёты).
5. Нажмите **Add key**.

Такой ключ действует **только для этого репозитория** и не даёт доступа к остальному в вашем аккаунте.

### Шаг 4. Проверьте связь с GitHub
В том же терминале (`lab@...`):
```bash
ssh-keyscan github.com >> ~/.ssh/known_hosts
ssh -T git@github.com
```
Ожидаемый ответ: `Hi behringer-hash/poly! You've successfully authenticated, but GitHub does not provide shell access.` Это успех. Если `Permission denied (publickey)` — см. раздел «Если что-то не так».

### Шаг 5. Скачайте код
```bash
git clone --branch claude/peaceful-mendel-yvwgus git@github.com:behringer-hash/poly.git ~/poly
exit
```
`exit` возвращает вас к основному пользователю (приглашение снова `ubuntu@...`).

### Шаг 6. Запустите установщик
```bash
sudo bash /home/lab/poly/ops/install.sh
```
Он занимает 2–5 минут и по шагам печатает «== 1/6 …». Что он делает: ставит пакеты, при нехватке памяти создаёт файл подкачки 2 ГБ, создаёт python-окружение, регистрирует две службы (`lab-collector` и `lab-runner`) и разрешает пользователю `lab` одну привилегированную команду — перезапуск службы записи. В конце напишет «Готово».

### Шаг 7. Убедитесь, что всё работает
```bash
systemctl is-active lab-collector lab-runner.timer
sudo journalctl -u lab-collector -n 30 --no-pager
sudo -u lab ls -la /home/lab/data
```
* Первая команда должна напечатать `active` дважды.
* Во второй должны быть строки `процесс cex запущен`, `процесс pm запущен`.
* В третьей через минуту-две появится папка с сегодняшней датой.

Через 5–10 минут откройте https://github.com/behringer-hash/poly/tree/server-results — там должна появиться папка `results` с первыми отчётами (`00_smoke_test` и `00_status`). Затем напишите мне «готово», и я прочитаю отчёт.

## Как этим пользоваться дальше
1. Вы говорите мне, что надо проверить («прогони реплей», «проверь задержки Bybit»).
2. Я пишу задание `jobs/once/<имя>.sh` (выполняется один раз) или `jobs/recurring/<имя>.sh` (повторяется, интервал задаётся строкой `# interval_min: 60`), проверяю его локально и сохраняю в ветку.
3. Через 5 минут сервер забирает и выполняет задание. Результат лежит в ветке `server-results`, я читаю его и объясняю вам.
4. Код записи (`run.py`, `cex.py`, `pm.py` и др.) сервер обновляет сам и сам перезапускает службу записи.

Чего я при этом **не могу**: выполнять команды на сервере мгновенно, видеть сырые данные целиком (только то, что задание положило в отчёт), торговать и видеть ваши ключи.

## Безопасность — что важно понимать
* Сервер выполняет скрипты из ветки `claude/peaceful-mendel-yvwgus`. Значит, **любой, у кого есть право записи в эту ветку, может выполнить код на сервере от имени пользователя `lab`**. Держите на GitHub двухфакторную защиту и не давайте право записи посторонним.
* Пользователь `lab` не имеет прав администратора, кроме перезапуска одной службы. Чтобы он не мог читать файлы вашего торгового бота, закройте домашнюю папку основного пользователя: `ls -ld /home/ubuntu` — если права `drwxr-xr-x`, выполните `sudo chmod 750 /home/ubuntu` (на новых Ubuntu это уже так). **Не кладите приватный ключ кошелька и файлы торгового бота в `/home/lab`** и не запускайте под `lab` живую торговлю.
* Если ключ утёк или вы хотите отключить сервер от репозитория: GitHub → Settings → Deploy keys → удалить `lab-server`. Задания перестанут выполняться.
* Ничего секретного в репозиторий не кладите. Служебные файлы уже исключены в `.gitignore`.

## Как остановить и удалить
Приостановить (данные остаются):
```bash
sudo systemctl disable --now lab-collector lab-runner.timer
```
Продолжить: `sudo systemctl enable --now lab-collector lab-runner.timer`.

Удалить всё без следа (данные тоже будут потеряны):
```bash
sudo systemctl disable --now lab-collector lab-runner.timer
sudo rm /etc/systemd/system/lab-collector.service /etc/systemd/system/lab-runner.service \
        /etc/systemd/system/lab-runner.timer /etc/sudoers.d/lab-collector
sudo systemctl daemon-reload
sudo deluser --remove-home lab
```
И удалите deploy key на GitHub.

## Если что-то не так

| Симптом | Причина и решение |
|---|---|
| `Permission denied (publickey)` на шаге 4 | Ключ не добавлен в GitHub или добавлен в другой репозиторий. Проверьте шаг 3: ключ должен быть в `behringer-hash/poly`, а в Title/Key не должно быть лишних пробелов и переносов строк. |
| `Repository not found` при `git clone` | То же: ключ не в том репозитории, либо ошибка в имени ветки. |
| `install.sh`: «Нет пользователя lab» / «Нет /home/lab/poly» | Пропущен шаг 1 или 5. |
| В `server-results` ничего нет через 10 минут | `sudo journalctl -u lab-runner -n 50 --no-pager`. Частые причины: ключ без права записи («Allow write access»), сервер не видит GitHub. |
| `active` не печатается для lab-collector | `sudo journalctl -u lab-collector -n 80 --no-pager` — пришлите мне последние строки. |
| Диск заполняется | Сырые данные старше `KEEP_DAYS` дней (по умолчанию 14) удаляются сами. Уменьшите значение в `/home/lab/lab.env`. |
| Мало памяти, процессы убиваются | Проверьте `free -m`. Нужны swap и тариф от 1–2 ГБ. Если на сервере ещё живой бот — возьмите отдельный инстанс. |
| Нужно сменить ветку | В `/home/lab/lab.env` строка `BRANCH=...`, затем `sudo -u lab git -C /home/lab/poly fetch origin`. |

## Обновление самой установки
Код записи и задания обновляются автоматически. Если я изменю файлы в `ops/systemd/` или `ops/install.sh`, я скажу об этом отдельно, и нужно будет заново выполнить `sudo bash /home/lab/poly/ops/install.sh` — повторный запуск безопасен.

## Для разработчика: проверка без сервера
`ops/test_runner.sh` создаёт временный «удалённый» репозиторий и проверяет всю логику runner'а: разовые и периодические задания, подхват новых заданий, отбрасывание больших файлов, таймаут.
